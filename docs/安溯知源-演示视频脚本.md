# 安溯·知源 VeriTrace · 3 分钟演示视频脚本

> 用途：传智杯 AI WEB 网页开发挑战赛参赛演示视频（时长控制在 3 分钟内，建议 2:50–3:00）
> 形式：屏幕录屏 + 画外旁白，关键画面配字幕条；不需要真人出镜
> 画幅：16:9 横屏；演示前先把浏览器缩放调到 100%，关闭无关标签页与消息弹窗
> 录制工具建议：OBS / 系统自带录屏，帧率 30fps，导出 1080p MP4
> 总原则：先讲结论再演示，每段画面对应一句可听见的旁白；AI 功能必须用真实 Key 跑通后再录

## 一、录制前检查清单（开播前逐项打勾）

- [ ] 后端已启动，数据库已导入全部 SQL（基础库 + 信任者体系 + 知识库 + 承诺种子数据）
- [ ] 环境变量 `AI_API_KEY` 已配置且有效，qwen-plus、qwen3-vl-plus、embedding-v3 均可调用
- [ ] 前端已重新 `npm run build`，产物在 `src/main/resources/static/app/`
- [ ] 准备好固定演示批次：溯源码 `TZ202603001001`
- [ ] 准备演示账号：管理员 `admin / 123456`、农户 `farmer / 123456`、经销商 `dealer / 123456`
- [ ] 准备一条新投诉用于 SLA 演示（若要展示超时标红，可提前改数据库 `overdue` 或缩短 `sla_hours`）
- [ ] 浏览器清空历史缓存，关掉翻译插件、广告拦截，避免遮挡页面
- [ ] 录一遍彩排：确认每一步加载不卡顿、AI 回答能在 10 秒内流式输出
- [ ] 准备降级预案：若 AI 接口临时不可用，旁白改为介绍规则文案兜底，不要在视频里暴露报错

## 二、旁白配音要求

- 语速：每分钟约 220–240 字，全片旁白控制在 700 字以内
- 音色：清晰平稳的青年男声/女声均可，语气是"讲解方案"不是"叫卖产品"
- 字幕：旁白关键句上屏为底部字幕条；页面内已有文字不重复打字幕
- BGM：选低音量纯音乐垫底（人声段压到 -20dB 左右），不要盖过旁白

### B02 ｜ 00:20–00:55 ｜ 可信指数与决策翻译（核心卖点一）

**画面**
1. 00:20–00:35：放大可信指数区域，依次展开五个维度：检测 30、农事 20、安全间隔期 20、流转 20、新鲜度 10；点击其中一项，展开对应真实证据（检测报告 / 农事记录 / 流转时间）。
2. 00:35–00:55：下移到决策翻译卡，展示结论分级（建议购买 / 注意核对 / 建议谨慎）、放心理由、风险提示、保存建议。

**旁白**
> 第一项核心能力是可信指数。它不用大模型主观打分，而是用确定性规则引擎从五个维度打分：检测、农事完整度、安全间隔期、链路完整度和新鲜度。
> 每一项分数都能点开看到真实证据，红黄绿分级。
> 在分数之上，我们做了决策翻译：把表格数据翻译成"建议购买、注意核对还是建议谨慎"，同时给出放心理由、风险提示和保存建议。

**画面文字**
- 维度标签：检测 30 · 农事 20 · 间隔期 20 · 流转 20 · 新鲜度 10

## 四、画面与剪辑注意事项

1. **顺序固定**：开场 → 可信指数 → 助手问答 → 承诺 → 售后 → 技术 → 收尾，与 PPT 第 5、8 页顺序一致，答辩时好呼应。
2. **录屏节奏**：每个点击动作后留 1–2 秒等待加载，不要快速拖拽鼠标；AI 流式回答至少停到回答完整输出。
3. **避免暴露风险**：不要录到 API Key、数据库连接串、本地磁盘路径；浏览器地址栏只保留应用路由。
4. **降级预案**：若录制当天 AI 接口不稳定，B03 助手段可先用规则文案演示，旁白说明"接入大模型后可结合历史事件多轮追问"，但答辩现场仍建议用真实 Key。
5. **字幕规范**：字幕放底部安全区，单行不超过 18 个字；专业术语首次出现给全称。
6. **版权**：BGM 选用无版权纯音乐；画面内不出现其他品牌 logo。

## 五、可选补充：被追问时的答辩口径

- **为什么可信指数不用大模型打分？** 分数要可复核、可追责，规则引擎每项都能对应到真实证据；大模型只负责把结果翻译成消费者能懂的话。
- **RAG 规模多大？** 演示知识库 126 条消费与标准知识，向量入库后余弦相似度 top-k，另有关键词降级检索。
- **如何防止越权？** 农户只能操作名下批次，经销商只看经手批次；消费者接口未建档返回业务错误，不强制跳登录。
- **作品边界是什么？** 不做交易履约，只做意向预约、常购提醒与责任追溯。
