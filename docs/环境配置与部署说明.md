## 二、环境变量模板

仓库根目录提供 `.env.example`，复制为 `.env` 后按实际填写；Docker Compose 会读取该文件。后端也支持通过操作系统环境变量注入，未配置时使用下列默认值。

| 变量名 | 是否必填 | 默认值 | 说明 |
|---|---|---|---|
| `DB_USERNAME` | 否 | `root` | 数据库用户名 |
| `DB_PASSWORD` | 否 | `123456` | 数据库密码；生产环境务必修改 |
| `AI_API_KEY` | 否 | 空 | DashScope API Key；留空则 AI 问答走规则降级文案。**线上已配置并通过真实调用验证** |
| `APP_BASE_URL` | 否 | `http://localhost:8080` | 生成二维码溯源链接的基础地址；线上设为 `http://47.243.26.118`，本地局域网演示时改为宿主机 IP |
| `AI_AGENT_MODEL` | 否 | `qwen-plus` | Agent 对话模型 |
| `AI_VL_MODEL` | 否 | `qwen3-vl-plus` | 多模态视觉模型 |
| `AI_EMBEDDING_MODEL` | 否 | `text-embedding-v3` | RAG 向量化模型 |

数据库连接由 `application.yml` 中的 `spring.datasource.url` 固定指向 `nongyeplus` 库；如需更换主机或端口，修改该配置项或通过对应环境变量覆盖。

## 五、本地开发启动步骤

### 5.1 初始化数据库

```bash
# 登录 MySQL 8.0，创建库（utf8mb4）

# 按顺序导入 SQL（sql 目录）
mysql -uroot -p123456 nongyeplus < sql/nongyeplus.sql
mysql -uroot -p123456 nongyeplus < sql/ai_knowledge.sql
mysql -uroot -p123456 nongyeplus < sql/upgrade_ai_evidence.sql
mysql -uroot -p123456 nongyeplus < sql/upgrade_trust_consumer.sql
mysql -uroot -p123456 nongyeplus < sql/trust_promise_seed.sql
mysql -uroot -p123456 nongyeplus < sql/consumer_knowledge_seed.sql
mysql -uroot -p123456 nongyeplus < sql/demo_trust_scenarios.sql
```

### 5.2 安装并构建前端

```bash
cd frontend
npm install
npm run type-check   # vue-tsc 严格类型检查，要求零错误
npm run build        # 产物输出到 src/main/resources/static/app/
```

### 5.3 启动后端

Windows PowerShell：

```powershell

mvn spring-boot:run
# 指定端口：mvn '-Dspring-boot.run.arguments=--server.port=8081' spring-boot:run
```

Linux / macOS：

```bash

mvn spring-boot:run
```

## 七、公网部署（线上实际环境）

线上为单机裸部署（非容器），便于在低配云主机上控制内存占用。目录与端口约定如下：

| 项 | 值 |
|---|---|
| 应用目录 | `/opt/nongye/`（Jar、上传目录 `uploads/`、日志 `app.log`） |
| 数据库 | `nongyeplus`，14 张表；账号 `nongye@localhost`（mysql_native_password） |
| 服务单元 | `/etc/systemd/system/nongye.service`，端口 8081，`Restart=on-failure` |
| 环境文件 | `/etc/nongye.env`，权限 `600`，由 `EnvironmentFile` 注入 |
| 反向代理 | `/etc/nginx/sites-available/nongye.conf`，80 → `127.0.0.1:8081`，AI 接口超时 180s |
| 公网入口 | http://47.243.26.118/ |

发布步骤：

```bash
# 1. 本地打包（前端产物须已内嵌到 src/main/resources/static/app/）
mvn -f pom.xml package -DskipTests

# 2. 上传并切换
scp target/nongye-0.0.1-SNAPSHOT.jar root@47.243.26.118:/opt/nongye/nongye.jar
ssh root@47.243.26.118 'systemctl restart nongye && systemctl is-active nongye'

# 3. 校验
curl -I http://127.0.0.1:8081/app/login     # 期望 200
curl -I http://127.0.0.1:8081/app/assets/index-*.js   # 静态资源须 200
```

部署时踩过并已修复的五个问题（重装时须注意）：

1. **页面白屏**：Jar 内 `static/app/assets` 文件数不足（旧增量打包漏了 vendor 分包），导致首页 HTML 正常但脚本 404。打包后应校验前端资源文件数与本地构建产物一致。
2. **溯源页报 `Table 'nongyeplus.trust_promise' doesn't exist`**：仓库基础 SQL 只含 8 张表，信任者体系另有 6 张表需单独补导，完整应为 14 张。
3. **管理端红字 `Unknown column 'overdue' in 'where clause'`**：只导基础表、漏跑 `sql/upgrade_trust_consumer.sql`，`complaint` / `crop_batch` / `scan_log` 共缺 11 个列。该脚本幂等，直接执行即可。
4. **AI 无输出但无报错**：密钥未注入或 `EnvironmentFile` 未生效，需 `systemctl show nongye -p EnvironmentFiles` 确认后再重启。
5. **页面加载慢**：`gzip_proxied` 默认 `off` 导致反代 JS 不压缩，且后端返回 `no-store` 无法缓存。已在 `nginx-nongye.conf` 开启 `gzip_proxied any` 并对 `/app/assets/` 设长缓存，1MB 组件下载由 14.6s 降至 2.26s。

## 八、常见问题排查

| 现象 | 排查方向 |
|---|---|
| AI 助手无流式回答或返回规则文案 | 检查 `AI_API_KEY` 是否有效、网络能否访问 DashScope；Key 留空属预期降级。线上环境用 `systemctl show nongye -p EnvironmentFiles` 确认 env 文件已加载 |
| 二维码链接手机打不开 | 线上确认 `APP_BASE_URL=http://47.243.26.118`（未设置会退化为内网 IP，扫码必失败）；本地方案改为宿主机 IP 并放行端口 |
| 前端页面 404 | 确认已执行 `npm run build` 且产物在 `src/main/resources/static/app/`，再重启后端 |
| 数据库连接失败 | 确认 MySQL 8.0 已启动、库名 `nongyeplus` 存在、账号密码与 `DB_PASSWORD` 一致 |
| 中文乱码 | 确认库与表字符集为 utf8mb4，连接串含 `characterEncoding=utf8` |
