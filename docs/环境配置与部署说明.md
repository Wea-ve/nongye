# 环境配置与部署说明（安溯·知源 VeriTrace）

> 适用项目：农产品全链路可信溯源决策平台
> 本文对应比赛提交要求中的「环境配置：提供完整的环境变量说明（含环境变量模板、依赖清单）」。

## 一、运行环境总览

| 类别 | 要求版本 | 说明 |
|---|---|---|
| JDK | 17（Eclipse Temurin / OpenJDK 17） | 后端编译与运行 |
| Maven | 3.9+ | 后端依赖管理与打包（项目自带 mvnw / mvnw.cmd 亦可） |
| Node.js | 20 LTS | 前端构建；Dockerfile 使用 node:20-alpine |
| npm | 随 Node 20 自带 | 前端依赖安装与构建 |
| MySQL | 8.0 | 业务库与知识库，字符集 utf8mb4 |
| 操作系统 | Windows 10/11、Linux、macOS 均可 | 本地开发以 Windows + PowerShell 为准 |
| 可选 | Docker 24+ / Docker Compose | 一键容器化部署 |

外部 AI 服务（可选，不配置时 AI 能力降级为规则文案，其余功能不受影响）：

- 通义千问 / 阿里云百炼 DashScope，需开通以下模型：
  - 对话模型 `qwen-plus`（Agent function calling）
  - 视觉模型 `qwen3-vl-plus`（图片识别）
  - 向量化模型 `text-embedding-v3`（RAG 检索）

## 二、环境变量模板

仓库根目录提供 `.env.example`，复制为 `.env` 后按实际填写；Docker Compose 会读取该文件。后端也支持通过操作系统环境变量注入，未配置时使用下列默认值。

| 变量名 | 是否必填 | 默认值 | 说明 |
|---|---|---|---|
| `DB_USERNAME` | 否 | `root` | 数据库用户名 |
| `DB_PASSWORD` | 否 | `123456` | 数据库密码；生产环境务必修改 |
| `AI_API_KEY` | 否 | 空 | DashScope API Key；留空则 AI 问答走规则降级文案 |
| `APP_BASE_URL` | 否 | `http://localhost:8080` | 生成二维码溯源链接的基础地址；手机扫码访问时改为宿主机局域网 IP，如 `http://192.168.1.8:8080` |
| `AI_AGENT_MODEL` | 否 | `qwen-plus` | Agent 对话模型 |
| `AI_VL_MODEL` | 否 | `qwen3-vl-plus` | 多模态视觉模型 |
| `AI_EMBEDDING_MODEL` | 否 | `text-embedding-v3` | RAG 向量化模型 |

数据库连接由 `application.yml` 中的 `spring.datasource.url` 固定指向 `nongyeplus` 库；如需更换主机或端口，修改该配置项或通过对应环境变量覆盖。

## 五、本地开发启动步骤

### 5.1 初始化数据库

```bash
# 登录 MySQL 8.0，创建库（utf8mb4）
mysql -uroot -p123456 -e "CREATE DATABASE IF NOT EXISTS nongyeplus DEFAULT CHARSET utf8mb4;"

# 按顺序导入 SQL（sql 目录）
mysql -uroot -p123456 nongyeplus < sql/nongyeplus.sql
mysql -uroot -p123456 nongyeplus < sql/upgrade_trust_consumer.sql
mysql -uroot -p123456 nongyeplus < sql/ai_knowledge.sql
mysql -uroot -p123456 nongyeplus < sql/consumer_knowledge_seed.sql
mysql -uroot -p123456 nongyeplus < sql/trust_promise_seed.sql
mysql -uroot -p123456 nongyeplus < sql/demo_trust_scenarios.sql
```

### 5.2 安装并构建前端

```bash
cd frontend
npm install
npm run type-check   # vue-tsc 严格类型检查，要求零错误
npm run build        # 产物输出到 src/main/resources/static/app/
```

### 5.3 启动后端

Windows PowerShell：

```powershell
$env:AI_API_KEY='sk-xxxx'   # 可选；不配置则降级为规则文案
mvn spring-boot:run
# 指定端口：mvn '-Dspring-boot.run.arguments=--server.port=8081' spring-boot:run
```

Linux / macOS：

```bash
export AI_API_KEY=sk-xxxx
mvn spring-boot:run
```

## 六、Docker Compose 一键部署

```bash
# 1. 复制并填写环境变量
cp .env.example .env

# 2. 构建并启动（MySQL 首次启动自动初始化基础库与知识库）
docker compose up -d --build

# 查看日志
docker compose logs -f app
```

- 宿主机 MySQL 端口映射为 `3307:3306`，避免与本机 3306 冲突。
- 应用端口 `8080:8080`；上传文件通过 `uploads-data` 卷持久化。
- 手机扫码访问前，将 `.env` 中 `APP_BASE_URL` 改为宿主机局域网 IP。

## 七、常见问题排查

| 现象 | 排查方向 |
|---|---|
| AI 助手无流式回答或返回规则文案 | 检查 `AI_API_KEY` 是否有效、网络能否访问 DashScope；Key 留空属预期降级 |
| 二维码链接手机打不开 | 将 `APP_BASE_URL` 改为宿主机局域网 IP，确认防火墙放行 8080 端口 |
| 前端页面 404 | 确认已执行 `npm run build` 且产物在 `src/main/resources/static/app/`，再重启后端 |
| 数据库连接失败 | 确认 MySQL 8.0 已启动、库名 `nongyeplus` 存在、账号密码与 `DB_PASSWORD` 一致 |
| 中文乱码 | 确认库与表字符集为 utf8mb4，连接串含 `characterEncoding=utf8` |
